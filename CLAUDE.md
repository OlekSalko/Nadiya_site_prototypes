Project Overview
Purpose

Develop a modern, visually appealing corporate website for a residential construction and real estate development company.

The company specializes in:

Construction of residential multi-apartment buildings.
Development of residential complexes.
Selling apartments in its residential buildings.

The website serves primarily as a digital company presentation and a marketing tool for showcasing residential projects and attracting potential apartment buyers.

The primary objective is to create a polished, professional, trustworthy, and visually engaging website.

Project Scope

IMPORTANT: This project is currently focused exclusively on visual presentation and layout development.

The website should be treated as a high-quality visual prototype rather than a fully functional production application.

Prioritize:

Visual quality.
Modern UI/UX design.
Consistent design language.
Responsive layouts.
Clear content hierarchy.
Attractive presentation of residential projects.
Professional corporate branding.

Do not spend time implementing complex business logic, backend functionality, databases, authentication, or real integrations.

Use static or mock data wherever necessary.

Technology Stack
Required Technologies

Use only:

HTML5
CSS3
Vanilla JavaScript (only when genuinely necessary)
Restrictions
Do not use frontend frameworks such as React, Vue, Angular, Svelte, or similar technologies.
Do not use CSS frameworks such as Bootstrap or Tailwind.
Do not introduce unnecessary dependencies or libraries.
Do not use build tools or complex development infrastructure unless explicitly requested.
Prefer native browser capabilities and standard web technologies.

The project should remain lightweight, simple, and easy to maintain.

Design Direction
General Visual Style

The website represents a professional residential construction and development company.

The visual identity should communicate:

Reliability.
Stability.
Professionalism.
Quality construction.
Modern architecture.
Trustworthiness.
Comfort and a high standard of living.

The design should feel premium, modern, clean, and elegant.

Avoid overly complicated layouts, excessive decoration, and unnecessary visual effects.

Color Palette

The primary visual identity is based on blue and white.

Preferred colors:

Navy blue.
Deep blue.
Corporate blue.
Medium blue.
Light blue.
Pale blue.
White.
Light neutral backgrounds.

Other colors are allowed when necessary, particularly for:

Text readability.
Subtle separators.
Shadows.
Status indicators.
Small decorative details.

Black or dark gray text is not prohibited, but prefer dark blue tones whenever appropriate.

Avoid introducing unrelated accent colors or overly colorful elements.

Maintain consistent color usage throughout the entire website.

Typography

Use modern, clean, highly readable typography.

Typography should:

Establish a clear visual hierarchy.
Be consistent across all pages.
Support both desktop and mobile layouts.
Use appropriate font sizes and line heights.
Give headings a strong visual presence.

Prefer a small and consistent typography system rather than arbitrary font sizes.

Responsive Design
Mobile-First Approach

Mobile-first development is mandatory.

Always design and implement layouts for mobile devices first, then progressively enhance them for larger screens.

The website must look polished and work correctly on:

Small mobile devices.
Standard smartphones.
Tablets.
Laptops.
Large desktop screens.

Requirements:

Use responsive CSS.
Prefer flexible layouts using Flexbox and CSS Grid.
Avoid fixed widths that cause horizontal overflow.
Ensure images scale correctly.
Make navigation comfortable on touch devices.
Maintain readable typography on smaller screens.
Adapt multi-column layouts to smaller viewports.
Keep spacing and proportions visually balanced across screen sizes.

Do not simply shrink desktop layouts to fit mobile screens. Adapt the composition and information hierarchy to the available space.

Website Structure

The website consists of:

Main landing page.
Individual residential project detail pages.

All pages must share a consistent visual identity and design system.

1. Main Landing Page

The landing page is the primary presentation of the company.

It should include the following sections:

Header / Navigation

Include:

Company logo or text-based brand identity.
Main navigation.
Navigation links to important sections.
Contact information or a prominent contact action.
Mobile navigation layout.

The header should be visually clean and consistent with the overall design.

Hero Section

Create a visually impressive introductory section.

It should communicate:

The company's identity.
Its specialization in residential construction.
Its value proposition.
A clear invitation to explore available residential projects.

Use high-quality architectural imagery.

The hero section should establish the visual tone of the entire website.

Company Introduction

Present a concise overview of the company.

Include:

Company description.
Main business activities.
Experience and professional positioning.
Key advantages.

Avoid large blocks of generic text.

Use a combination of typography, imagery, and structured content.

Create a dedicated section presenting important company achievements.

Example metrics:

Number of apartments sold.
Number of completed residential buildings.
Number of residential projects.
Years of experience.
Number of satisfied customers.

Use visually prominent statistics.

Numbers should be easy to scan and should contribute to the company's credibility.

Use realistic placeholder values where actual company data is unavailable.

This is one of the most important sections of the website.

It should present residential buildings currently available for purchase.

Project cards should include:

Project image.
Residential complex name.
Location.
Short description.
Construction or completion status.
Starting apartment price (if relevant).
A link or visual action to view project details.

The layout should be attractive and easy to browse.

Use responsive grids that adapt to different screen sizes.

Visually distinguish available projects from completed or sold-out projects where appropriate.

Why Choose Us

Create a section explaining the company's competitive advantages.

Possible content:

Construction quality.
Modern architecture.
Convenient locations.
Thoughtful apartment layouts.
Transparent purchasing process.
Reliable construction practices.

Present these advantages using concise descriptions and appropriate visual elements.

Social Media

Include a section or clearly visible links to the company's social media profiles.

Use recognizable social media icons or simple branded links.

The design should make these links easy to find without distracting from the main content.

Use placeholder profile links if real URLs are not provided.

Contact Section

Include a contact section with:

Company phone number.
Email address.
Office address.
Social media links.
Contact form.

The contact form is primarily a visual component.

It should include typical fields:

Name.
Phone number.
Email address (optional).
Message.

Do not implement backend submission or external integrations.

The form only needs to look professional and have appropriate input styling.

Footer

Include:

Company logo or name.
Short company description.
Navigation links.
Contact information.
Social media links.
Copyright notice.

The footer should be visually consistent with the website's branding.

UI/UX Principles

Follow these principles throughout the project:

Visual hierarchy must be clear.
Important information must be easy to find.
Navigation must be intuitive.
Calls to action must be visually distinguishable.
Content should be easy to scan.
Spacing should be consistent.
Components should follow a unified design language.
Mobile layouts must receive the same attention as desktop layouts.

The website should look like a professionally designed corporate website, not a basic HTML template.

Code Quality

Even though this is primarily a visual project, maintain clean and understandable code.

Requirements:

Use semantic HTML5 elements.
Keep CSS organized and reusable.
Use CSS variables for colors, typography, spacing, and other design tokens.
Use meaningful class names.
Avoid unnecessary CSS duplication.
Keep JavaScript minimal.
Avoid inline styles unless there is a good reason.
Maintain consistent formatting.
Use accessible HTML elements and appropriate labels.
Add meaningful alt attributes to images.
Ensure interactive elements have clear hover and focus states.

Prefer reusable components and consistent patterns, even without using a frontend framework.

Development Workflow

When working on a new task:

Inspect the existing project structure before making changes.
Understand the current implementation and visual conventions.
Identify the relevant files.
Follow the established design system.
Implement the requested changes.
Check the result at mobile and desktop viewport sizes.
Verify that there is no horizontal overflow.
Check that typography, spacing, and imagery are visually consistent.

For larger tasks, first analyze the requirements and propose an implementation plan before modifying the code.

Do not unnecessarily rewrite existing code or introduce new dependencies.

Scope Restrictions

Unless explicitly requested, DO NOT:

Implement backend functionality.
Create database schemas.
Implement authentication.
Implement real payment functionality.
Integrate CRM systems.
Implement real contact form submission.
Build complex business logic.
Add unnecessary animations.
Introduce frontend frameworks.
Add unnecessary dependencies.
Spend time optimizing functionality that is outside the visual prototype scope.

Basic visual interactions are acceptable when they improve the presentation.

Definition of Done

A task is considered complete when:

The requested visual elements have been implemented.
The design follows the established blue-and-white visual identity.
The layout is mobile-first and responsive.
The result looks polished on both mobile and desktop.
Existing pages maintain visual consistency.
HTML and CSS remain clean and maintainable.
No unnecessary frameworks or dependencies have been introduced.
No horizontal overflow or obvious layout issues exist.
The implementation matches the requested visual scope.

Final Priority: Visual quality, professional presentation, responsive design, and consistent branding are more important than complex functionality.

Language Rules

The user may write requests in Ukrainian.

If a request is written in Ukrainian, first translate it into English, then work from the English version of the request.

Respond in English unless the user explicitly asks otherwise.

Prototype Versioning Structure

The project holds several independent prototype attempts instead of using branches or repositories for versions.

Each attempt lives in its own subfolder in the project root, named спроба_1, спроба_2, and so on.

Each attempt is a self-contained website (its own index.html, css, js, assets, and project pages) and must not depend on files from other attempts.

The root index.html is only a lightweight launcher page with links to each attempt's index.html.

When a new attempt is created, add it to the list of links in the root index.html.

Do not modify previous attempts unless explicitly asked.
